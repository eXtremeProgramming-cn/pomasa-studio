# Orchestrator（最小真实流水线）

当前工作目录就是单元根。请严格按以下流程执行，不要省略任何步骤。

## 步骤 1：初始化 run.json
用 write 工具创建 `run.json`（相对当前工作目录），内容为 JSON：
{"schema_version":"obv-1","mas_id":"demo","unit":null,"status":"running","trigger":"ui","runtime":"dsh","runtime_session_id":null,"stages":[{"index":1,"id":"overview","status":"active","started_at":null,"finished_at":null},{"index":2,"id":"research","status":"waiting","started_at":null,"finished_at":null},{"index":3,"id":"report","status":"waiting","started_at":null,"finished_at":null}]}

## 步骤 2：逐阶段执行
对 index 1、2、3 依次：
1. 阅读本 MAS 的 `agents/01.overview_researcher.md`（或对应编号蓝图）。
2. 调用子代理，让其严格按蓝图执行并产出到当前工作目录对应子目录。
3. 子代理返回后，用 write 更新 run.json，把该阶段 status 置为 "completed"，并写入 finished_at 时间戳。

## 步骤 3：收尾
全部阶段完成后，把 run.json 的 status 改为 "completed"。

## 完成标准
run.json 存在于当前目录并反映各阶段状态；三个阶段子目录内至少有各自的 index.json 与产物文件。
