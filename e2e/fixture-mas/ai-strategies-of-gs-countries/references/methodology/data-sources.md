# 数据来源指南（Data Sources）

> 本文件规定收集阶段的数据来源类型、可信度评级、SRC 记录格式与抓取工具优先级（STR-06 + BHV-05 + BHV-06）。所有涉及联网收集与核验的代理必须遵循。

## 来源类型与可信度评级

| 序号 | 来源类型 | 示例 | 优先级 | 可信度 |
|------|----------|------|--------|--------|
| 1 | 政府官方文件 | 国家级 AI 战略/路线图/白皮书、总统令/行政命令、部委文件、议会立法文本、官方门户 | 高 | **高** |
| 2 | 国际组织 | 联合国（及其机构）、UNESCO、OECD、ITU、世界银行、IMF、区域组织（非盟、东盟、G20/BRICS 公报） | 高 | **高** |
| 3 | 智库/研究机构 | 该国国家级研究院、大学研究中心；国际知名智库（Carnegie、Brookings、CSIS、RAND、Chatham House 等） | 高 | **中高** |
| 4 | 权威主流媒体 | Reuters、AP、AFP、FT、BBC 及该国主流大报/主流电视台（如巴西 Folha、印度 The Hindu、南非 News24 等） | 中高 | **中高** |
| 5 | 行业报告 | 咨询公司（麦肯锡、BCG 等）、行业协会、科技媒体深度报道（TechCrunch、The Verge、Rest of World 等） | 中 | **中** |
| 6 | 学术文献 | arXiv、SSRN、ResearchGate、同行评审期刊 | 中 | **高** |
| 7 | 企业/项目官网 | 公司公告、项目白皮书（如主权云、大模型发布页） | 中 | **中**（以官方渠道发布的为准） |

### 需谨慎使用或避免的来源

- 个人博客、匿名自媒体（无机构背书）：避免
- 明显商业推广/广告性质内容：避免
- 无发布主体、无日期的来源：避免
- 社交媒体帖文：仅可作线索，不能作为事实来源（官方账号发布除外）
- 搜索摘要：**绝对不是数据**，只是发现 URL 的线索（BHV-05）

## 多语种检索提示（针对国别研究）

- 每个国家尽量使用**官方语言 + 英语**双语检索（如巴西用葡萄牙语、沙特用阿拉伯语）；政府文件优先抓官方语言版本。
- 谨慎辨别**同名机构/同名人物**（如不同国家的“AI 委员会”）；以官方域名与正式标识为准。
- 对“传言”“未官方证实”的信息，宁可记录为“据媒体报道”并标注低置信度，也不强行确认。

## SRC 记录格式（收集阶段强制）

每条材料一个独立 Markdown 文件（一个 SRC 文件 = 一个来源 = 一次抓取）：

```markdown
# [SRC-{dir}-{NN}] 页面/文档标题

**Source URL**: https://example.com/document （单一裸 URL，禁止加注释、拼接）

**Fetch Time**: 2026-08-31T00:00:00Z

**Source Type**: 政府官方文件 / 国际组织 / 智库报告 / 权威媒体 / 行业报告 / 学术文献 / 企业官网

**Credibility**: 高 / 中高 / 中 / 低（依据来源权威性判断，与内容好坏无关）

**Original Content**:

[抓取到的完整原文，逐字保留；不得改写、提炼、转述、重排或加小标题]
```

### 硬性规则（违反即返工）

1. **Source URL 必须是单一裸 URL**：不得有括号注释、双 URL 拼接、说明文字。
2. **原文逐字保存**：抓取返回什么就保存什么（段落、链接、标题结构原样）；**禁止**“要点提炼”“关键信息提取”“改写成列表”；保存后自检长度（若明显短于原文，如只剩 1/10，说明做了摘要，必须重做）。
3. **一个 SRC 文件一个来源**：多个来源支撑同一观点 = 写多个 SRC 文件。
4. **搜索摘要不可引用**：页面抓不到就换替代 URL → 换同主题其他来源 → 仍失败则把该信息记入“信息缺口”，绝不回退使用摘要。
5. **关键事实多源交叉**：关键数据（投资额、立法时间、芯片/算力规模、协议条款等）尽量收集 ≥2 个独立来源；单一来源的关键事实在记录中显式标注“单一来源”。

## 抓取工具优先级（BHV-06）

**搜索工具**（按优先级尝试）：

1. `mcp__serper-search__google_search`（如已配置）
2. `WebSearch`（运行时内置，兜底）

**网页抓取工具**（按优先级尝试）：

1. `mcp__crawl4ai__read_url`（如已配置，免费，多数页面可用）
2. `mcp__oxylabs__universal_scraper`（如已配置，处理难抓页面）
3. `mcp__oxylabs__ai_scraper`（如已配置；部分环境版本为 `mcp__oxylabs__ai_search`，功效相同）
4. `WebFetch`（运行时内置，最终兜底）

实际使用中：优先**免费/廉价的 MCP 工具**，失败再依次降级；全部失败才报告失败。若运行时提供其他抓取手段（如 `curl` 直连抓取），可视为 WebFetch 的同级兜底。

## 核验后引用规则（QUA-03）

- 只有列入 `03.verification/verified_sources.md`（保留清单）的 SRC 才能被分析、分节与报告引用。
- 被“剔除”的 SRC：任何阶段不得引用。
- 被“降级”的 SRC：仅可在明确标注其低可信度后引用，且不得作为关键事实的唯一支撑。

## 数据记录质量自检清单

- [ ] 每条 SRC：裸 URL + Fetch Time + Source Type + Credibility + 逐字完整原文
- [ ] 无“要点提炼式”记录（发现一处即不合格）
- [ ] 关键事实 ≥2 个独立来源（不足则显式标注“单一来源”）
- [ ] 未使用任何搜索摘要内容
- [ ] 来源类型与可信度评级符合上表
